# protoST benchmarks — 2026-09-29

- **Host:** AMD Ryzen 5 5500U with Radeon Graphics, 12 logical CPUs, Linux 7.0.0-34-generic
- **Load average (1 min):** 1.30 before, 2.62 after
- **protoST:** protoST 0.4.0 at commit `d3f7235`
- **CPython:** Python 3.14.0; **protoPython:** `/usr/bin/protopy`
- **Method:** 2 warmup + 5 timed runs per measurement; median wall-clock, min–max in parentheses. Every run verified its result (`VERIFIED` / `BENCH_RESULT`); a failed run fails the harness.

## Start-up

A process that evaluates one expression: protoST 27.2 ms (26.5–28.7), CPython 29.1 ms (28.4–42.9). The comparable workloads below use small N, so start-up is part of every time.

## Actors

- **Parallel speedup** (12 CPU-bound actors): 731.6 ms with one worker, 348.7 ms with the default pool: **2.10×**.

## Reading these numbers

- **Start-up dominates the small workloads.** Whole-process ratios (geomean
  3.45×) mostly compare two similar start-ups; the work itself is slower:
  from about 6× CPython (`int_sum_loop`) to about 36× (`fib`, recursive
  method dispatch) and 64× (`exception_latency`), geomean 20.8× over the
  five workloads long enough to measure (`list_append` and `str_concat`
  take under 0.5 ms of work in CPython, so their work ratio is not
  meaningful at this N).
- **Parallel scaling tops out at about 2.1×** (four workers) for
  `saturation_big`, and 2.1× for twelve CPU-bound actors with the default
  pool. The one-minute load was 1.3–2.6 (desktop applications); an
  independent re-run at load 0.7 the same night gave the same curve
  (2.14× at four workers), so this is the build's ceiling on this laptop,
  not an effect of the load. The May 2026 figure of 3.88× started from a
  single-worker time 2.5× slower than today's.
- Every number above is a median of five verified runs; a run that did not
  report the expected result would have failed the harness.
