# protoST benchmarks — 2026-09-29

- **Host:** AMD Ryzen 5 5500U with Radeon Graphics, 12 logical CPUs, Linux 7.0.0-34-generic
- **Load average (1 min):** 2.90 before, 5.15 after
- **protoST:** protoST 0.4.0 at commit `8e5274f`
- **CPython:** Python 3.14.0; **protoPython:** `/usr/bin/protopy`
- **Method:** 2 warmup + 5 timed runs per measurement; median wall-clock, min–max in parentheses. Every run verified its result (`VERIFIED` / `BENCH_RESULT`); a failed run fails the harness.

## Start-up

A process that evaluates one expression: protoST 27.8 ms (26.6–31.1), CPython 31.0 ms (28.5–40.1). The comparable workloads below use small N, so start-up is part of every time.

## Actors

- **Parallel speedup** (12 CPU-bound actors): 750.7 ms with one worker, 364.7 ms with the default pool: **2.06×**.
- **Cooperative yield:** 1000 actors, each parked on a `wait`, on 2 worker threads: 681.4 ms.
- **Message throughput:** 2000 round-trip sends (send + `wait`): 108.1 ms, about 18,503 round trips per second including start-up.

## Conditions and caveats

- **The machine was not idle.** Desktop applications (an IDE and a browser)
  kept the one-minute load between 2.9 and 5.2 during the run. The
  single-thread times are within a few percent of interleaved idle-ish
  checks made the same night; the **parallel figures (speedup, worker
  scaling) are lower bounds**: with other processes on the cores, adding
  workers past four does not help. An earlier idle measurement (May 2026,
  `2026-05-23-performance.md`) reached 3.88× at six workers on the same
  laptop. An idle re-run is pending before these numbers are quoted as the
  release figures.
- Every workload runs a small N, so the ~28 ms process start-up is part of
  each time; CPython's start-up is about the same.
- Known slow spots, reported as measured: recursive method dispatch (`fib`,
  about 10× CPython) and exception signalling (`exception_latency`, about
  24×).
