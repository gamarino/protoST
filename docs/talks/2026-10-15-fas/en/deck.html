Why it is possible now

protoCore: one core, several languages

Immutable

Collections that are "modified" by creating a new version that shares almost everything with the previous one.

Parallel

Native threads with no global lock and a concurrent garbage collector.

Shared

JavaScript, Python, Clojure, Scala and protoST on the same object model.

Three properties, one example of each if asked. protoCore is a separate project; protoST is its demonstrator.

The idea that makes it safe

A mutable object is a reference to an immutable snapshot

account

atomic reference

{ owner: Ana balance: 120 }

snapshot: nobody changes it

A message to another thread carries a reference, not a copy, and every read sees a consistent snapshot: never a half-written state.

Modifying installs a new snapshot; whoever held the previous one still sees it whole. That is why passing objects between threads needs neither copies nor locks.

Actors

Any object can be an actor

c := Counter new asActor.
1 to: 1000 do: [:i | c increment].
c increment wait "=> 1001"

Every message returns a Future at once (except identity, nil and printString, which the proxy answers).

The actor processes one message at a time: its state is plain instance variables, with no locks.

Actors share a pool of native threads.

wait, thenDo:, whenAll:. An error inside the actor comes back, with its class, to whoever is waiting. An actor that is waiting does not handle other messages; if two actors wait on each other, protoST reports it as an error.

Demo 2 · real parallelism

The same computation, on one thread and on twelve actors

futures := ranges collect: [:r |
PrimeCounter new asActor countFrom: r first to: r last].
parallel := futures inject: 0 into: [:sum :f | sum + f wait]

Both results must agree (4946 primes); the times are measured live.

Run ./run_demo.sh 02-actors-parallelism.st. State the speedup that appears on screen, not one from memory. The code of the computation did not change: what changed is who runs it.

Ideas, not promises

Worlds it could open up

Digital twins

One actor per physical component: each event is processed atomically and the components talk through messages.

Services

What protoST is not

All written down and verified

— No image or browser: the program is the file

— A blank line ends a method

— Immutable strings (WriteStream to build them)

— Short symbols equal to strings

— Thin metaclass; no thisContext

— An actor that is waiting does not handle other messages
