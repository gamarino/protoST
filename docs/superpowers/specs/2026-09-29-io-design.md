# Input and output for protoST (0.5.0)

Decision: the author, 2026-09-29 — "sé generoso con la entrada/salida, que
nadie lo sienta limitado". Before this, a protoST program could only print:
no files, no standard input, no arguments, no environment, no processes, no
network. The talk's positioning ("your code where Smalltalk does not reach:
digital twins, services, simple interfaces to other systems") needs all of it.

## Shape

- **Pharo names where Pharo has them**, so a Smalltalk programmer guesses
  right: `Smalltalk arguments`, `Stdio stdin nextLine`,
  `'data.txt' asFileReference contents`, `writeStreamDo:`, `/`, `children`.
- **A thin C++ layer, a Smalltalk API.** `src/primitives/io_prims.cpp` exposes
  low-level `__…` primitives on integers (file descriptors), strings and
  arrays; the classes are protoST code: `lib/kernel/io.st` (always loaded),
  `lib/net.st` and `lib/http.st` (loaded with `Import from:`, so scripts that
  do not use the network pay no start-up time for it).
- **Every blocking call leaves the GC quorum** (`ProtoContext::UnmanagedScope`,
  the ProtoThread convention `sleep:` already follows), touching no protoCore
  object while blocked, so an actor waiting on a socket never stalls a
  collection.
- **Errors are classed and catchable**: `FileDoesNotExist`, `FileAlreadyExists`,
  `FileSystemError`, `ConnectionRefused`, `ConnectionTimedOut`,
  `NameLookupFailure`, `NetworkError`, `OSProcessError`; all are `Error`s.
- Text is UTF-8 `String`; binary data is an `Array` of integers 0–255
  (`ByteArray` is not implemented in protoST).

## API

**System** — `Smalltalk arguments` (Array of Strings, the script's own
arguments), `Smalltalk programPath`, `Smalltalk getenv: 'HOME'` (nil when
unset), `Smalltalk environment` (Dictionary), `Smalltalk setenv: k to: v`,
`Smalltalk exit: code`, `Smalltalk quit`, `Smalltalk pid`, `Smalltalk hostName`,
`Smalltalk platform`, `Smalltalk workingDirectory` (a FileReference),
`Smalltalk changeDirectory: path`.

**Standard streams** — `Stdio stdin` / `stdout` / `stderr` (also
`Transcript` for output). Reading: `nextLine` (nil at end), `upToEnd`,
`next`, `next: n`, `atEnd`, `linesDo:`, `lines`. Writing: `nextPutAll:`,
`nextPut:`, `print:`, `display:`, `<<`, `cr`/`lf`/`crlf`, `space`, `tab`,
`flush`.

**Files** — `'path' asFileReference` or `File named: 'path'`, and
`FileSystem workingDirectory`, `FileSystem home`, `FileSystem temp`.
A FileReference answers `exists`, `isFile`, `isDirectory`, `size`,
`modificationTime` (epoch ms), `fullName`, `pathString`, `basename`,
`basenameWithoutExtension`, `extension`, `parent`, `/ 'child'`,
`children`, `files`, `directories`, `contents`, `contents:`
(replace), `appendContents:`, `lines`, `linesDo:`, `binaryContents`,
`binaryContents:`, `readStream`, `writeStream`, `appendStream`,
`readStreamDo:`, `writeStreamDo:`, `appendStreamDo:` (the stream is closed
when the block ends, also on error), `createFile`, `createDirectory`,
`ensureCreateDirectory`, `delete`, `ensureDelete`, `deleteAll`, `copyTo:`,
`moveTo:`, `renameTo:`. File streams answer the stream protocol above plus
`close`.

**Processes** — `OSProcess run: 'ls' arguments: #('-l')`,
`run:arguments:input:`, `shell: 'ls | wc -l'`, `shell:input:` answer an
`OSProcessResult` (`exitCode`, `output`, `errorOutput`, `succeeded`);
`OSProcess command: 'git rev-parse HEAD'` answers the output (without the
final newline) and signals `OSProcessError` on a non-zero exit;
`OSProcess spawn: 'cmd' arguments: #()` answers a pid, with
`OSProcess waitFor: pid` and `OSProcess kill: pid`.

**Network** (`Import from: 'net'`) — `Socket connectTo: 'host' port: 80`
(`timeout:` variant), a stream with the protocol above plus `close`,
`peerName`, `timeout:`, `tlsHost:` (upgrades to TLS with certificate and
host-name verification); `ServerSocket listenOn: 8080` (`listenOn:host:` for one interface,
port 0 picks a free port, `port` answers it), `accept`,
`acceptTimeout:`, `close`; `UDPSocket bindTo: port`, `send: data to: host
port: p`, `receiveTimeout: ms` (answers `{data. host. port}` or nil).

**HTTP** (`Import from: 'http'`) — `HTTPClient get: url`, `post: url body:
string`, `post:json:`, `put:body:`, `delete:`, `request: method url: url
headers: dict body: string`; http and https; chunked bodies; redirects
followed (up to 5); `timeout:`. An `HTTPResponse` answers `status`,
`reason`, `headers` (lower-case keys), `body`, `json`, `isSuccess`.
`HTTPServer on: 8080 handler: [:request | …]`: the handler answers an
`HTTPResponse` (`ok:`, `json:`, `status:body:`, `notFound`,
`contentType:`), a String (200, text/plain) or any other object (200, its
JSON); `start` serves on the calling thread, `startInBackground` on an
actor, `stop`. Each connection is handled by its own actor. A request
answers `method`, `path`, `query` (Dictionary), `headers`, `body`, `json`.

## Out of scope (documented)

HTTP/2, WebSockets, a TLS server, non-blocking multiplexing (`select` on many
sockets from one actor: use one actor per connection), Windows.

## Tests

Conformance programs for each area (files in a temporary directory, a local
TCP/UDP echo, a local HTTP server queried by the client, a local TLS
handshake failure path), CLI tests for arguments, stdin, stderr and exit
codes, and a GC test that collects while actors block on sockets.

## Review hardening (2026-09-29)

A code review of the first implementation found defects that this design did
not rule out explicitly; they were fixed before the release:

- **Shared descriptors.** Actors may use one stream at once. Each descriptor
  has a read lock, a write lock and, for TLS, a lock held only around one
  non-blocking OpenSSL call; the state owns the descriptor, so `close` shuts a
  socket down (waking a blocked reader) and the number is released only when
  the last user returns.
- **SIGPIPE.** Writes other than the program's own standard output block the
  signal on the writing thread, so a child that exits without reading its
  input, or a peer that goes away, raises a catchable error instead of ending
  the process.
- **TLS timeouts.** A TLS socket is non-blocking; the handshake, reads and
  writes wait in `poll` with the socket's timeout.
- **Worker pool growth.** The pool's lock is never held across the
  allocation that creates a worker thread.
- **HTTP.** Control characters in a method, URL or header are refused;
  chunked bodies are decoded as bytes; percent-decoding reads UTF-8 and `+`
  is a space only in the query; relative redirects resolve per RFC 3986, a
  redirect to another origin drops the program's headers and https-to-http
  is refused; request and header lines, header count and body size are
  bounded on the server (414, 431, 400, 413); a handler error answers a plain
  500 and is reported on standard error.
- **Kept as designed.** A program does not exit while an actor is blocked in
  I/O (an unclosed `accept` keeps it alive); `Smalltalk exit:` ends it.
